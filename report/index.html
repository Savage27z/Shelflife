How much NEAR contract source can anyone actually check?

A blockchain runs machine code. Projects publish readable source and say “this is what it does.” Almost nobody checks whether a link goes anywhere, or whether the two match. This measures the first of those, across NEAR mainnet.

1. Only 6 of 168 token contracts publish source that could be rebuilt

Of 168 token contracts inspected, only 6 (3.6%) publish a source link that both resolves and is pinned to a commit — the minimum anyone would need to rebuild the code and compare it with what is deployed.

A link is not source. The 34 contracts that carry a link point at only 13 distinct GitHub repositories. 4 of them return 404 (gone, or private), and 1 contract publishes a literal template placeholder such as https://github.com/<xxx>/<xxx>. Of the links that do resolve, only 8 of 33 name a commit; the rest point at a repository front page, which cannot be tied to a particular deployed version.
Metadata presence overstates verifiability. 19 of the 53 contracts exposing metadata publish no link in it — a version string pointing nowhere.
Accounts are not programs. Those 168 accounts run only 101 distinct pieces of bytecode, because factories deploy clones. Counting distinct programs, 41.4% of the 87 unique-bytecode contracts expose metadata.

Wrapped NEAR holds the backing for every wNEAR in existence, so one account dominates the total. Quote the headline with this table, never without it. This counts NEAR balance only: a token contract’s value to its users is in the tokens it issues, which this does not capture. Treat it as a floor, not a measure of risk.

What this does and does not claim

Verification coverage, not honesty. A contract publishing no source is unverifiable. That is not evidence anyone is lying, and no project is accused of anything.

Nothing has been rebuilt. Every figure measures what is published, not whether it compiles to the deployed bytes. “Rebuildable” means a rebuild would be possible, not that one was done.

A 404 is ambiguous. GitHub returns the same for a deleted repository and a private one.

The tooling is Rust-only. Every one of the 105 current-registry records is Rust, and NEP-330 metadata comes from Rust tooling, so a contract written in another language cannot carry it. The share of non-Rust contracts in the sample was not measured, so part of the gap here may be structural.

The sample is token contracts, which may not behave like the rest of the chain. The registry counts in section 2 are complete for both SourceScan registries; they are not a statement about verification elsewhere (an explorer may hold records of its own).
